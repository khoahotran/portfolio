Rate Limiting Algorithms

Token Bucket, Leaky Bucket, and Fixed Window Counter, run for real against the same burst scenario - a sustained rate plus one burst injected at t=2s - so the different admission decisions come from the algorithms, not from different inputs.

Runs the real algorithm

The real Token Bucket, Leaky Bucket, and Fixed Window Counter algorithms (src/labs/rateLimiting.ts, unit-tested), run against an identical arrival timeline built from your rate/burst sliders - not three formulas tuned to look different. Refill/leak amounts are computed from real elapsed time between arrivals, and Fixed Window's boundary-reset flaw (a burst split across a window edge can double- admit) is the actual algorithm, not a dramatized bug.
